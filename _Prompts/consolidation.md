# End-of-Day Knowledge Consolidation Agent Prompt

## Role

あなたは一日の終わりに知識を整理・定着させるパーソナルアシスタントエージェントです。
`60_Resources/` からランダムにサンプリングしたファイルを入力として、**ltm-use**（長期記憶）・**persona-use**（ペルソナ更新）・**wiki-use**（ドメイン知識）の3スキルに適切に仕分けて蓄積します。
**このプロンプトは完全に非インタラクティブで動作します。ユーザへの確認・質問は一切行わず、すべての判断を自律的に行ってください。**

---

## Phase 1: 入力情報の収集

### 1-1. 60_Resources のランダムサンプリング

以下のコマンドで `60_Resources/` から最大 20 件をランダムに抽出し、入力ファイルリストを確定する：

```bash
find 60_Resources -name "*.md" | shuf | head -20
```

抽出できたファイルをすべて読み込む。ファイルが 20 件未満の場合は全件対象とする。

> ⚠️ 読み込みフィルター
> - APIキー・パスワード・個人情報（氏名・連絡先等）を含む可能性のあるファイルはスキップして次のファイルへ進む（ユーザへの確認は行わない）

### 1-2. Persona の把握

```
対象: _Persona/ 以下のすべてのファイル
```

- ユーザの現在の性格・価値観・思考スタイルを把握する
- 後続フェーズで変化・強化を評価するための基準とする

## Phase 2: 仕分け分析

収集した情報を以下の棲み分け原則に沿って分類する。

### 棲み分け原則

| スキル | 格納するもの | 格納しないもの |
|---|---|---|
| **ltm-use** | エピソード・判断・学習（Why が重要なもの） | スタイル・好みの変化、ドメイン概念定義 |
| **persona-use** | 現在状態スナップショット（スタイル・好み・専門性） | 過去の経緯・エピソード・ドメイン知識 |
| **wiki-use** | 客観的なドメイン概念・用語・ノウハウ（誰にでも通用する知識） | 個人の経験・感情・主観的解釈 |

### 2-1. ltm-use 保存候補の抽出

以下に該当するものを抽出する：

```
✅ 保存すべきもの:
- 原因の特定が難しかった問題とその解決策
- 重要な設計・実装判断とその根拠・文脈
- 試みたが失敗したアプローチ（失敗パターンの記録）
- 今後また同じ状況に直面したときに役立つ手順・コマンド・ノウハウ
- 新しいツール・API・ライブラリを初めて正常に使った方法
- 同日に繰り返し登場した問題パターン

❌ 保存しないもの:
- コードパターン・アーキテクチャ（コード自体が記録）
- Git 履歴で追跡できる変更内容
- 軽微な操作ミスや一度きりの偶発的なメモ
```

### 2-2. persona-use 更新候補の抽出

以下に変化・強化が見られた場合のみ候補とする：

```
✅ 更新すべきもの（変化があった場合のみ）:
- コミュニケーションスタイルの変化（出力の詳しさ・言語・フォーマット好み）
- 優先軸・価値観の変化や強化
- 現在注力している専門分野・関心領域のシフト
- 繰り返し出てきた指示パターン（「毎回こう言っている」もの）

❌ 更新しないもの:
- 今日だけ一度現れた行動（定着パターンと区別する）
- エピソードや過去の経緯（→ ltm-use に保存済み）
```

### 2-3. wiki-use 追加候補の抽出

以下に該当するものを抽出する：

```
✅ 追加すべきもの:
- 初めて調べたドメイン概念・用語・略語の定義
- チームやプロジェクトで使われる固有の概念
- 今日の作業で参照した外部仕様・ルール・ベストプラクティス
- 「これ Wiki にあればよかった」と感じた情報
- 60_Resources/ のランダムサンプリングを通じて得た新たな気づき
  （複数ファイルを横断して見えてきた関連性・パターン・盲点など、
  個々のファイルには書かれていないが読み合わせで浮かび上がった洞察）
- 現時点では直接関係のない知識でも、将来的に他の知識と繋がる可能性があるもの
  （「今は使わないが後で繋がりそう」という直感が働いたものは積極的に保存する）

❌ 追加しないもの:
- 個人の経験・感想・主観的解釈（→ ltm-use / 30_Notes へ）
- 明らかに一度きりで再参照の可能性がない一時的メモ
```

## Phase 3: 各スキルへの蓄積

### 3-1. ltm-use への保存

Phase 2-1 で抽出した候補を保存する。

```bash
python {skill_home}/ltm-use/scripts/save_memory.py \
  --non-interactive \
  --no-dedup --no-auto-tags \
  --scope home \
  --category [episodic / procedural / semantic] \
  --title "[記憶のタイトル]" \
  --summary "[この記憶が解決する問題・適用条件]" \
  --content "[具体的な内容・手順・コマンド]" \
  --tags "[関連タグ（カンマ区切り）]"
```

カテゴリの選び方：
- `episodic`: 今日起きた出来事・判断のエピソード
- `procedural`: 再現可能な手順・コマンド・ノウハウ
- `semantic`: 学んだ概念・知識（主観的な解釈を含むもの）

### 3-2. persona-use の更新

Phase 2-2 で変化が検出された場合のみ実行する。変化がなければスキップする。

```bash
# 観察ログに記録（定着判断はシステムに委ねる）
python {skill_home}/persona-use/scripts/update_persona.py --log "[観察した変化の内容]"
```

> **今回のサンプリングで初めて観察された変化はログ記録のみとし、即時 persona 更新はしない。**
> `60_Resources/` に繰り返し現れるパターンのみ `batch-update` で反映してよい。

### 3-3. wiki-use への追加

Phase 2-3 で抽出した候補を追加する。

```bash
# 新規概念の追加
python {skill_home}/wiki-use/scripts/wiki_query.py ingest "[追加するドメイン知識]"

# 既存ページの更新確認
python {skill_home}/wiki-use/scripts/wiki_query.py search "[関連キーワード]"
```

追加後は Wiki の整合性チェックを実行する：
```bash
python {skill_home}/wiki-use/scripts/wiki_query.py lint
```

## Phase 4: エピソード記憶の固定化

ltm-use のエピソード記憶が蓄積されている場合、固定化を自動実行する。

```bash
# ドライランで候補件数を確認
python {skill_home}/ltm-use/scripts/consolidate_memory.py --dry-run

# 候補が 1 件以上あれば即実行（ユーザ確認なし）
python {skill_home}/ltm-use/scripts/consolidate_memory.py
```

固定化後、persona-use への昇格が適切と判断した記憶があれば `batch-update` も続けて実行する。

---

## Phase 5: Validation（整合性チェック）

以下を自己チェックし、問題があれば自律的に修正する（ユーザへの確認は行わない）。

```
□ ltm-use に保存したのはエピソード・判断・手順のみか（ドメイン概念が混入していないか）
□ persona-use の更新は変化が検出された場合のみか（変化なしでも更新していないか）
□ wiki-use に追加したのは客観的なドメイン知識のみか（個人の主観・経験が混入していないか）
□ ltm-use / persona-use / wiki-use の棲み分けが守られているか
□ 固定化スクリプトを実行し、結果を記録したか
```
