### 概要
Karpathy氏が公開したAIエージェントによる自動改善フレームワーク「autoresearch」の概念を、Railsアプリケーションのサーバーサイド・パフォーマンスチューニングに応用する仕組みを解説しています。AIに自律的な改善サイクル（PDCA）を回させるため、安全性を確保する「ハーネスエンジニアリング」の手法を詳述しています。

### 要点まとめ

#### 1. autoresearch の基本原理
- **固定された評価基準**: 評価関数を固定し、公平な比較を行う。
- **固定された時間予算**: 実験時間を一定に保ち、小さな改善を積み重ねる。
- **進化的選択圧**: 改善すればKeep、悪化すればDiscard（ロールバック）し、常に最良の状態を維持する。

#### 2. パフォーマンスチューニングへの転用
- 「コード変更 → ベンチマーク → 判定」のサイクルをAIに10分間隔で自律実行させる。
- エンジニアが寝ている間も実験を回し続け、数百回の改善試行を自動化する。

#### 3. AIを安全に動かす「ハーネスエンジニアリング」
- **サブエージェントの分離**: チューニング担当とデータセットアップ担当に分け、テストデータの内容をAIに見せないことで、データへの過学習を防止。
- **読み取り制限（Read hook）**: ベンチマーク関連ファイルへのアクセスをhooksでブロック。
- **Bashコマンド制限**: ホワイトリスト方式により、許可された安全なコマンドのみを実行可能に制限。
- **ブランチ保護**: 特定プレフィックスのブランチ以外では動作しないよう制御。

#### 4. 実行環境の構築
- **SKILL.md**: AIの行動指針（セットアップ・ラン・防御機構）を定義。
- **再帰的学習**: 試行履歴（`tuning_results.tsv`）を読み込ませることで、過去の成功・失敗からエージェントの改善精度を向上させる。
