### 記事の要約
本記事は、AIエージェントフレームワーク「C3 (Claude Code Conductor)」の作者が、ユーザーからの指摘や公式仕様との衝突を通じて、コンテキストの最適化と運用改善を行った記録です。

### 主な要点
- **コンテキストの削減 (10.8k tokens)**
    - 問題：`rules/` 配下の長文ガイドラインが全セッションで強制的にロードされ、トークンを圧迫していた。
    - 解決：対象ファイルを `skills/dev-workflow/references/` へ移動させ、必要時のみロードされる構成に変更。
    - 教訓：AIに提案を求める際は「公式仕様」だけでなく、実機の `/context` 出力による「実測」を突き合わせることが不可欠。
- **Claude Code 公式とのコマンド衝突対応**
    - 問題：公式の新機能追加により `code-review` コマンドが衝突。
    - 解決：C3側のスキル名を `/review-phase` へリネーム。
    - 仕組み：`DEPRECATED_PATHS`定数を導入し、アップデート時に廃止パスが残存していれば警告を表示する自動検知機能を実装。
- **今後の運用・教訓**
    - 派生フレームワークは、公式の更新に追従するだけでなく、衝突を機械的に防ぐ回帰テスト（`test_skill_no_builtin_conflict.py`等）が重要。
    - AIは概念（例：適用範囲の限定 vs ロードコスト削減）を混同しやすいため、人間側が概念を厳密に切り分けて確認する必要がある。
