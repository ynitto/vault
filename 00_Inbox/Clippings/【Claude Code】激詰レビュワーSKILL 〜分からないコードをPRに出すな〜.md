### 要約
AIによるコーディング支援が普及する中で、「なぜそのコードを書いたのか」を説明できないまま実装が増えるリスクを回避するため、Claude Codeを「激詰レビュワー」として活用する手法の紹介です。PR作成前にAIから厳しい質問攻めを受け、実装内容や設計判断を自己理解・言語化することで、エンジニアとしての学習機会を確保し、コードの品質と保守性を担保します。

### 重要なポイント
- **AI活用時の課題**
    - 実装への理解度が低いままAIがコードを生成し、PRに紛れ込む問題。
    - 理由を説明できないコードは、レビュワーの負担増や保守時の調査難易度上昇を招く。

- **「激詰レビュワーSKILL」の概要**
    - Claude CodeのSKILL機能を利用し、実装方針・アーキテクチャ・副作用・エッジケースについて人間を詰めるAIを構築。
    - 「答えを教えず選択肢を提示する」形式により、ユーザー自身に考えさせ理解を深めさせる。
    - 完了後、やり取りを`GEKIDUME_REVIEW.md`にまとめ、PR作成の振り返り資料として活用。

- **PRレビューへの展開**
    - 別のSKILL(`post-grill-to-pr`)により、レビューでのQA要約をPRの該当行にインラインコメントとして反映。
    - レビュワーが設計意図を直接確認できる状態を作り、コミュニケーションコストを削減する。

- **本手法の利点**
    - **自己成長**: 調査・回答プロセスを通じてコードの深い理解が得られる。
    - **品質向上**: 実装前後のエッジケース検討や設定値の再考により、事前に穴を塞げる。
    - **説明責任**: レビュワーに対して論理的な説明が可能になる。
